## Limits and deliberate partial behavior

- Missing `proposal.runId` is `invalid_request`; admit before reasoning. The
  general Proposal schema remains optional for this field, while this public
  operation requires it at runtime.
- Composition and nonempty claim `unknowns` are explicitly `unsupported`, so no
  submitted information is silently discarded. Composition references are not
  individually authorized because this slice rejects composition entirely.
- A claim statement over 512 characters is `limit_exceeded`, never shortened.
  Findings are `unverified`; indexed metadata matching is not a digest or
  reasoning proof. Existing aggregate and response limits remain enforced.
- Host budgets are declarations. Think-Wide does not control or account for
  model calls made outside its process.
- A public stale/cancelled/epoch-changed submission throws a contract error;
  all writes roll back. An epoch-rejected public call alone therefore does not
  persist a `superseded` status. Internal publication still returns its rejection
  and commits `superseded`. Human decisions supersede active runs atomically.
- Receipt replay rereads currently authorized result IDs. It does not promise an
  immutable historical response body after subsequent authorized human changes.
- Adding host admission and binding proposal submission updates generated
  inventory-dependent test counts.
