1. `submitProposal` has no handler. A model driving the loop through MCP has no tool to
   publish a claim; publication exists only as `internal.runs.publish`. Blocks T10 on the
   MCP-host path. Owner: Marc / contract owner.
2. `prepareHandoff` and `readHandoff` have no handler. The brief step has nothing behind
   it. Pinned by a test in `t11-loop.test.ts` that fails when a handler lands. Owner: Marc (T09).
3. `searchSources` and `readGuidance` have no public handler; `getCapabilities` reports
   `searchModes: []`. T07's search code is not reachable as an operation. Owner: Eassa.
   Without it the demo is browse plus exact read, and must say so.
4. On `andrew/I01-identity` (`62dd428`) the browser never gives Convex a token. WorkOS
   login works and `convex/auth.config.ts` trusts the WorkOS issuer, but the root route
   mounts the plain `ConvexProvider`, not an authenticated one. Every browser call to
   Convex is anonymous and the handlers answer `unauthenticated`. Login is proven;
   login-to-backend identity is not. Owner: Andrew (I01).
5. Local-demo has one fixed principal. Every agent on the stdio path is the same identity
   with the same grants. There is no per-agent authorization and A/B cannot be shown
   through MCP in this mode.
