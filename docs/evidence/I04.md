`i04-recovery-proof`; no principal, grant, user token or auth bypass was introduced.
Its full result including Convex document ID/creation time was saved privately.

1. `control.py backup` produced `20260920T204345Z-c29815`: exit 0. Backend and
   private TLS stopped before archiving; both restarted healthy afterward.
2. `control.py restore --project think-wide-restore-rehearsal
   --root /opt/think-wide-restore-rehearsal --backend-port 43210
   --actions-port 43211 --backup <that-directory>`: exit 0, separate volumes.
3. `control.py bootstrap` with those restore arguments: exit 0. Restore network
   inspected as `Internal=true`; its backend had **no published port bindings**.
4. Convex CLI in a temporary container attached only to that internal network read
   the restored data. Document ID, creation time and all contents exactly matched.
   Production's post-restart row also matched. Function inventories were identical;
   the restored deployment environment still read `connected`.
5. The entire backup was copied off-host via SSH into an ignored 0700 local
   directory; every manifest checksum matched. Secret files stayed 0600.
6. Restore containers were stopped. Production private backend/TLS remain healthy.

Two verification adjustments are explicit: Docker 29 does not expose ports on an
internal restore network, so a host-forwarded CLI could not inspect it; verification
moved inside that network. Copying only the CLI bundle omitted `esbuild`, so its normal
Convex 1.46.0 dependencies were installed in a separate admin-tools volume before
running the inspector offline. No restored backend received outbound connectivity.

This proves recovery using the **same pinned backend** and the pushed schema/functions,
plus one real database row. It is not a populated user-portfolio recovery benchmark,
file-storage API test, cross-version downgrade or proof of reconciling post-backup
writes. The runbook requires paired pre-migration backups for incompatible rollbacks.
